# JobLovesMe Agent 项目执行路线图 (todo.md)

## 一、 执行策略 (总)
本项目采用 **“快速上线 MVP，持续迭代增强”** 的分阶段策略。
- **目标**: 在 4 周内完成从“核心功能跑通”到“生产级治理”的全面进化。
- **重点**: 优先保证简历与打招呼的“体感”，随后深挖面经爬取与 RAG 的“深度”，最后通过监控大盘实现“量化管理”。

---

## 二、 阶段性执行计划 (分)

### 2.1 Phase 1: MVP 核心链路 (第 1 周)
**目标**: 实现最基础的简历上传与打招呼推荐。
- [ ] **底座搭建**: 
  - Docker Compose 启动 MySQL, Redis, Milvus。
  - 初始化 Go Gin 后端与 React 前端脚手架。
- [ ] **简历模块**: 
  - 实现 PDF 解析与本地持久化。
  - 完成 JWT 基础登录/注册功能。
- [ ] **打招呼生成**: 
  - 实现基于 DeepSeek 的推荐语生成 API。
  - 前端完成拖拽上传与文本展示 UI。
  ## 2.1.5 MVP 验证与反馈阶段 (当前焦点)
  **目标**: 部署 MVP，在真实求职场景中使用，并记录 AI 表现。
  - [ ] **环境部署**: 成功在本地运行前后端，并配置好 DeepSeek API。
  - [ ] **真实测试**: 投递 3-5 个真实岗位，使用 Agent 生成打招呼文本。
  - [ ] **记录反馈**: 在 `feedback.md` 中记录：
    - AI 生成的文本是否需要大幅修改？
    - PDF 解析是否准确（有没有乱码或遗漏）？
    - 前端交互是否有卡顿或不直观的地方？

### 2.2 Phase 2: 监控与质量治理 (第 2 周)
**目标**: 让 AI 的效果可见、可量化，并加入安全保护。
- [ ] **可观测性基础**: 
  - 集成 Prometheus 与 Grafana。
  - 在 Go 后端埋点统计 API 耗时与状态码。
- [ ] **安全加固**: 
  - 实现 PII 脱敏中间件，保护用户隐私。
- [ ] **质量评估**: 
  - 引入 `Judge Agent` 对推荐语进行初步打分。
  - 开始收集 Bad Case 到数据库。

### 2.3 Phase 3: 工程架构升级 - Eino & 异步 (第 3 周)
**目标**: 引入工业级编排，解决性能与存储瓶颈。
- [ ] **Eino 编排**: 
  - 使用 Eino 重新构架 RAG 检索链路。
  - 实现 Eino Rerank 节点，进行 A/B Test 效果对比。
- [ ] **异步爬虫流**: 
  - 实现 Redis Stream 任务分发逻辑。
  - Python 爬虫接入 Consumer，并实现“最小堆流式过滤”算法。
- [ ] **性能优化**: 
  - 引入 Redis 语义缓存 (Semantic Cache)，降低重复请求成本。

### 2.4 Phase 4: 模拟面试与全量大盘 (第 4 周)
**目标**: 完成高价值业务闭环。
- [ ] **模拟面试系统**: 
  - 基于 Eino 状态机实现多轮对话面试。
  - 实现多维度面评（技术雷达图逻辑）。
- [ ] **全量大盘**: 
  - 在前端实现 Dashboard 页面，集成 Grafana 图表与业务统计。
  - 展示 Token 成本、召回率、成长曲线。
- [ ] **文档沉淀**: 
  - 导出 A/B Test 实验数据，完成《项目完结技术总结报告》。

## 三、 持续迭代与远景 (总)

### 3.1 迭代策略
- **反馈驱动**: 每一周结束必须自己作为真实用户试用 10 次，记录痛点并更新到下一周的任务中。
- **文档同步**: API 变更必须实时更新 `docs/openapi.yaml`，确保前后端协同不脱节。

### 3.2 3.0 版本远景
- **多 Agent 协同**: 引入 LangGraph 实现跨 Agent 自动决策（如：Agent 自动判断是否需要为用户购买额外的付费面经）。
- **个性化学习建议**: 结合面评数据，自动爬取相关技术视频或博客并推送给用户。
